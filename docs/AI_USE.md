# Use of AI in LUMEN

Space Apps allows AI-generated content when the reason is stated, the prompts are explained,
and the team's own creative work is visible. Keep this file current as the project changes;
align its wording with the official Project Submission Guide when it publishes on 13 November 2026.

## 1. AI inside the product

**Component:** the "Ask about this prediction" assistant (`src/components/Assistant.tsx`,
`src/assistant/`, `server/index.mjs`).

**Why a language model is used:** to turn a prediction, its probabilities and the nearest
recorded NASA burns into a short plain-English explanation that a non-specialist can follow.

**What the language model does not do:** it never computes a number. The gradient-boosted
classifier (`src/model/flex.ts`, trained by `ml/train_flex.py`) produces the prediction; the
nearest-experiment lookup (`src/model/neighbors.ts`) is a deterministic range-normalised
distance over the PSI-69 table; the "what if" figures are real model evaluations
(`src/assistant/grounding.ts`). All of this is assembled into a JSON grounding in the browser
and shown to the user under "What the assistant was shown".

**Prompt:** the system prompt lives in `server/index.mjs` (`SYSTEM_PROMPT`). It instructs the
model to use only the grounding, quote numbers exactly, cite row ids, flag extrapolation, and
refuse questions the grounding cannot answer. The user message is the grounding JSON plus the
question.

**Model:** configured in `.env` (`LLM_PROVIDER`, `LLM_MODEL` or `AZURE_OPENAI_DEPLOYMENT`).
Record the model actually used for the demo here before submission:

- Model: Azure OpenAI deployment `gpt-5.4-mini` (same resource as the DIU Ai Assistant project)
- Provider / endpoint: Azure OpenAI, `api-version=2025-04-01-preview`
- Date of demo recording: _—_

**Offline behaviour:** with no model configured, or with the network off, the same grounding
is rendered by a deterministic template (`src/assistant/offline.ts`) and the answer is labelled
"computed from the table". Answers from the model are cached in `cache/chat/` and can be frozen
into `demo_fixtures/chat.json` with `npm run freeze` so the rehearsed demo questions answer
identically offline; those are labelled "cached answer".
